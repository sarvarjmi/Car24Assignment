# Document Objective

This document defines the **complete Home Screen architecture**.

The Home Screen is the core of the assignment.

Unlike a traditional Compose screen:

- No widgets are hardcoded.
- No UI hierarchy is manually created.
- Entire UI comes from Room JSON.
- Renderer converts JSON → Compose.

The Home Screen demonstrates the complete Server-Driven UI platform.

---

# 1. Home Screen Philosophy

The Home Screen is **generic**.

It knows nothing about:

- Banner
- Search
- Chips
- Car Cards
- CTA

It only knows:

```text
HomeScreen

↓

RendererHost

↓

Renderer

↓

Component Registry

↓

Compose Widget
```

---

# 2. Responsibilities

The Home Screen is responsible for

- Observing Room
- Displaying Loading UI
- Displaying Error UI
- Hosting Renderer
- Dispatching User Actions

The Home Screen never

- Parses JSON
- Knows widget types
- Reads Room
- Creates widgets manually

# 29. Performance Strategy

The Home Screen should naturally:

- Observe only one `StateFlow`
- Avoid unnecessary recompositions
- Use stable parameters
- Use LazyColumn/LazyRow
- Render only visible items
- Cache parsed models where appropriate
