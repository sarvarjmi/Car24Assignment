# Document Objective

This document defines the complete **Versioning Strategy** for the entire project.

Versioning ensures the application can evolve without breaking:

- JSON Schema
- Renderer
- Database
- Components
- Features
- Modules
- Documentation
- Future Backend Integration

The objective is to support **backward compatibility**, **controlled evolution**, and **safe migrations**.

---

# 1. Versioning Philosophy

Every layer of the project has its own version.

Each version evolves independently while maintaining compatibility contracts.

```text id="version01"
Application

↓

Database

↓

JSON Schema

↓

Renderer

↓

Components

↓

Documentation
```

# 3. Semantic Versioning

All versions follow **Semantic Versioning (SemVer)**.

```text id="version02"
MAJOR.MINOR.PATCH
```

Example

```text id="version03"
1.2.5
```

Meaning

- Major → Breaking changes
- Minor → New features
- Patch → Bug fixes

---

# 4. Application Version

Gradle

```text id="version04"
versionCode

versionName
```

Example

| Property | Value |
|----------|-------|
| versionCode | 1 |
| versionName | 1.0.0 |

Rules

- versionCode always increases.
- versionName follows SemVer.

---

# 5. Database Version

Room maintains

```text id="version05"
DATABASE_VERSION
```

Increment only when:

- Table changes
- Index changes
- Foreign key changes

Never increment for business logic changes.

---

# 6. JSON Schema Version

Every payload contains

```json id="version06"
{
  "schemaVersion": "1.0.0"
}
```

Purpose

- Validation
- Compatibility
- Migration

---

# 7. Renderer Version

Every renderer exposes

```text id="version07"
rendererVersion
```

Renderer validates schema compatibility before rendering.

---

# 8. Component Version

Each widget supports

```json id="version08"
{
  "componentVersion": "1.0.0"
}
```

Future widget upgrades remain backward compatible.

---

# 9. Theme Version

Theme payload contains

```json id="version09"
{
  "themeVersion": "1.0.0"
}
```

Allows theme evolution without changing renderer.

---

# 10. Configuration Version

Application configuration stores

```text id="version10"
configurationVersion
```

Used for future feature flags and runtime configuration.

---

# 11. Version Compatibility Matrix

| JSON | Renderer | Result |
|------|----------|--------|
| Same | Same | ✅ Render |
| Older | Newer | ✅ Compatible |
| Newer | Older | ⚠️ Fallback / Reject |
| Invalid | Any | ❌ Reject |

---

# 12. Database Migration Strategy

Migration flow

```text id="version11"
Old Database

↓

Migration

↓

Validation

↓

New Database
```

Rules

- Preserve user JSON.
- Never lose component data.
- Test every migration.

---

# 13. JSON Migration Strategy

Migration flow

```text id="version12"
Old JSON

↓

Migration

↓

Validation

↓

Renderer
```

Only validated payloads proceed.

---

# 14. Component Evolution Rules

Allowed

- Add optional properties
- Add new widget types
- Add new actions

Not Allowed

- Remove required properties
- Rename mandatory fields
- Break existing payloads

---

# 15. Deprecation Policy

Deprecated features

```text id="version13"
Supported

↓

Deprecated

↓

Migration Available

↓

Removed (Next Major Version)
```

Never remove features abruptly.

```text id="version20"
Migration

↓

Rollback

↓

Previous Stable State
```

# 26. Version Naming Convention

Use

```text id="version24"

1.1.0

1.2.0

2.0.0
```

```text id="version25"
final

new

test
```

---

# 27. Compatibility Rules

Always support

- Older JSON (within supported major version)
- Older renderer-compatible payloads
- Existing Room data after migration

Never silently ignore incompatible major schema versions.

---

# 28. Testing Strategy

Test

- Database migration
- JSON migration
- Renderer compatibility
- Version validation
- Rollback
- Seed upgrades

---

# 29. Best Practices

Always

- Use Semantic Versioning
- Version JSON
- Version Renderer
- Version Database
- Maintain CHANGELOG
- Test migrations

Never

- Break compatibility without a major version
- Skip migration tests
- Remove required fields in minor releases
- Ignore version mismatches
